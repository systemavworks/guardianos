04 — Arquitectura de Seguridad

Diseño Seguro por Capas

GuardianOS Audit implementa un modelo de defensa en profundidad con separación estricta de responsabilidades entre capas.

Autenticación

JWT firmado HS256 · bcrypt factor 12 · API keys hasheadas SHA-256 · Sin almacenamiento de contraseñas en texto plano

Red y TLS

TLS 1.3 exclusivo · HSTS · CORS restrictivo · Solo puertos 80/443 expuestos · Servicios internos en red Docker privada no enrutable

Base de Datos

PostgreSQL con usuario sin permisos superuser · Queries parametrizadas (Exposed ORM) · Sin SQL dinámico · Aislamiento por tenant a nivel de datos

Integridad Forense

Cada auditoría genera un hash SHA-256 único e irrepetible · Encadenamiento blockchain-lite entre auditorías del mismo objetivo · Verificación pública sin autenticación

Agentes

Token único por agente · Comunicación HTTPS · Sin acceso root requerido · Firma SHA-256 de cada payload enviado · Sin datos de sistema en tránsito sin cifrar

IA (Claude)

Invocación bajo demanda exclusiva · El informe base no envía datos a Anthropic · Solo texto de hallazgos (sin IPs ni datos personales) llega a la API de Claude · Controlado por el operador

Stack tecnológico auditado

Backend:    Kotlin 1.9 · Ktor 2.x · Exposed ORM · PostgreSQL 16 · Redis 7
Frontend:   React / Vite · TypeScript · Tailwind CSS
Infra:      Docker Compose · nginx (TLS 1.3 + HSTS) · MinIO (S3-compatible)
Auth:       JWT (HS256) · bcrypt (factor 12) · API keys SHA-256
Certs:      Let's Encrypt (ACME) autorenewable
Código:     AGPL-3.0 · guardianos.es/audit/security
05 — Protección de Datos

Qué datos recopilamos y cómo los tratamos

GuardianOS Audit sigue el principio de privacidad por diseño (GDPR Art. 25) y minimización de datos. La plataforma puede desplegarse completamente auto-hospedada sin compartir ningún dato con nosotros.

Datos NO almacenados

✓ Contraseñas en texto plano
✓ Credenciales SSH
✓ Claves API de terceros
✓ Contenido de ficheros auditados

Datos de cuenta

Email (hash en logs), nombre de organización, preferencias de notificación. Necesarios para el servicio. Eliminables bajo solicitud.

Datos de auditoría

Dominio / IP auditado, hallazgos técnicos, score, timestamp. Propiedad del usuario. Exportables y eliminables desde el dashboard.

Datos de agente

Fingerprint del sistema (hash), versión OS, CVEs detectados. Sin información personal de usuarios del sistema auditado. Aislados por tenant.

Base legal (RGPD)

  • Ejecución de contrato (Art. 6.1.b) — datos necesarios para prestar el servicio de auditoría.
  • Interés legítimo (Art. 6.1.f) — logs de seguridad para detección de abuso.
  • Consentimiento (Art. 6.1.a) — análisis IA opcional; el usuario activa explícitamente el envío a Claude.

Para ejercer derechos ARCO: info@guardianos.es · Ver Política de Privacidad completa.

06 — Divulgación Responsable

Política de Reporte de Vulnerabilidades

Agradecemos los reportes responsables de la comunidad de seguridad. Esta política aplica exclusivamente a GuardianOS Audit (guardianos.es/audit).

Alcance

  • API REST: guardianos.es/api/v1/*
  • Dashboard web: guardianos.es/audit
  • Backend Kotlin/Ktor (código abierto AGPL-3.0)
  • Agentes Linux/Windows (scripts del repositorio)

Fuera de alcance: ataques DoS volumétricos, ingeniería social, servicios de terceros (Cloudflare, GitHub, Anthropic).

Cómo reportar

Envía tu reporte cifrado con nuestra clave PGP a info@guardianos.es con asunto [SECURITY-AUDIT] descripción breve.

Clave PGP: https://guardianos.es/pgp-key.txt
Fingerprint: 8D5D 2148 485D BFD3 1BFC 3DDB 2F50 61C4 7E2B F14F

Tiempos de respuesta

≤ 72 h Confirmación de recepción del reporte
≤ 7 días Evaluación técnica y clasificación de severidad (CVSS v3.1)
≤ 14 días Parche para vulnerabilidades críticas (CVSS ≥ 9.0)
≤ 30 días Parche para vulnerabilidades altas (CVSS 7.0–8.9)
Publicación CVE / advisory público tras resolución coordinada; mención en hall-of-fame con consentimiento del investigador
